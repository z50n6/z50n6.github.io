Linux 入侵排查

2025-11-05 Linux ， 应急响应

0、应急响应流程

当企业发生黑客入侵、系统崩溃或其它影响业务正常运行的安全事件时，急需第一时间进行处理，使企业的网络信息系统在最短时间内恢复正常工作，进一步查找入侵来源，还原入侵事故过程，同时给出解决方案与防范措施，为企业挽回或减少经济损失。

针对常见的攻击事件，结合工作中应急响应事件分析和解决的方法，总结了一些 Linux 服务器入侵排查的思路。

排查主流程：

  1. 摸现状：系统信息、时间、历史命令
  2. 查网络与进程：连接、端口、进程及隐藏手法
  3. 查账号与访问后门：用户权限、SSH 公钥后门
  4. 查持久化：开机启动项、计划任务、服务、shell 启动文件
  5. 查文件与命令完整性：可疑文件、命令替换、SUID
  6. 日志分析与时间线：secure、journald、auditd、rsyslog

现场保护与取证顺序：

先隔离再取证（断网/快照/保留现场），取证按易失性顺序：内存 → 网络连接 → 进程/会话 → 磁盘文件。失陷机上先采集、后处置，别急着 kill 进程或跑全盘扫描，避免破坏证据。

处置要点：

清除后门后要复查一遍全部持久化点，防止清了又起来；取证材料先留存再处置。

一、摸现状：系统与历史

1.1 系统信息与时间

内核信息：

先确认内核版本，为下一步提权漏洞推论做铺垫——如果存在相关提权漏洞，一定和操作系统内核有关系。

uname -a 输出解析：3.10.0-693.el7.x86_64 中 3.10.0 是内核版本、el7 是发行版（RHEL/CentOS 7）、x86_64 是架构。提权漏洞几乎都跟着内核版本走（如 DirtyCow CVE-2016-5195、DirtyPipe CVE-2022-0847），对照内核版本即可快速判断有没有已知提权 EXP 可用。

/proc/version 显示的是内核信息，/etc/*-release 显示的是发行版信息，两者用途不同。

系统时间确认：

注意时区：EDT（美国东部夏令时，UT-4）比 CST（中国标准时间，UT+8）晚 12 小时。系统时间和本地时间不匹配时，后续系统日志、应用日志的时间都要重新换算。

换算例子：日志里的 07:00 EDT（UTC-4）= 北京时间 19:00（UTC+8）。如果系统时区异常或日志时间对不上，先看 /etc/localtime 和 timedatectl，攻击者可能用 date -s 改过时间伪造日志。

二、网络与进程排查

2.1 网络连接与端口

使用 netstat 网络连接命令，分析可疑端口、IP、PID

TCP 状态快速判断：LISTEN 本地在监听、ESTABLISHED 已建立连接、SYN-SENT 正在主动外连（还没收到 ACK，可能是扫描器或回连失败）、TIME_WAIT 正常关闭后的残留。对外发起的 ESTABLISHED / SYN-SENT 连接是重点。

新系统推荐用 ss 替代 netstat：ss -tulnp 效果等同 netstat -antulp。

补充判断：

  • ss -tnp state established 只看已建立的连接，重点盯非业务端口的外连
  • DNS 隧道特征：大量大体积 TXT 查询、高频率随机子域名；ICMP 隧道：正常环境极少用 ICMP 传数据，出现异常 ping 流量要查

发现可疑IP，上报或者威胁情报分析，确认后结束进程

查看下 pid 所对应的进程文件路径，如果确认是病毒，及时上报进行留存与删除

进程隐藏手法与排查（攻击者怎么藏，我们怎么找）：

1、偷梁换柱（替换命令）

原理：不藏进程本身，而是替换 top/ps/lsof 这类查看命令，让命令在输出正常内容的同时过滤掉恶意进程。这种手法安全防护人员也会用，比如隐藏蜜罐里的监控进程，不让入侵者察觉。

实验思路（攻击者复现）：

排查思路：

  • stat /bin/ps、/bin/top 等命令文件，看 mtime 是否在事发时间附近（正常系统 /bin 下的 mtime 通常很旧）
  • find /bin/ /sbin/ -mtime 0 查一天内被修改的命令文件
  • md5sum /bin/ps 与同版本干净系统对比，不一致就是被替换
  • 更彻底：rpm -Va 校验所有 rpm 包文件完整性（见 7.1 工具篇）

2、Hook 系统调用（LD_PRELOAD）

原理：/proc 是一个虚拟文件系统，是 VFS（虚拟文件系统）的一个实现形式，里面包含内核信息、硬件信息、进程信息。ps/top 这类工具并不是直接查进程表，而是通过分析 /proc 文件系统中进程相关目录来获取进程信息。

ps 的工作流程：先调用 openat 系统函数拿到 /proc 目录的文件句柄 → 调用 getdents 系统函数递归获取 /proc 下所有文件信息（包括子目录）→ 再调用 open 打开 /proc//stat、/proc//status、/proc//cmdline 等文件获取进程信息 → 最后整理打印。

Hook 的原理：这种隐藏方式是拦截或迷惑 ps 等工具从 /proc 获取分析结果的过程，而不是修改 /proc 文件系统本身。比起劫持修改 getdents 之类的函数，更简单的是利用环境变量 LD_PRELOAD 或配置 /etc/ld.so.preload 文件，让恶意动态库先于系统标准库加载，最终实现对特定进程的隐藏。

3、可疑账号排查

  • sudoers 三列含义：root ALL=(ALL) ALL——第一个 ALL 允许从任何终端执行、第二个 (ALL) 允许以任何用户身份、第三个 ALL 允许执行所有命令；NOPASSWD: ALL 免密 sudo 风险更高
  • /etc/sudoers 默认权限 440（仅可读），发现可写权限要警惕
  • 攻击者常把 sudoers 改成可写（如 chmod 744）再往里面塞提权规则，ll /etc/sudoers 看权限就能发现
  • /etc/group 里 root:x:0: 后面没列出用户是正常的（root 初始用户不显示），出现非 root 用户名就要警惕
  • 确认可疑后禁用/删除：usermod -L user（/etc/shadow 第二栏变为 !）、userdel user、userdel -r user（连家目录一起删）

4、攻击者常用的建号手法（对照排查）

  • 基本组与附加组：创建用户时默认生成一个同名基本组（不能移除），其他组都是附加组（可删除）；一个用户只能有一个基本组，可属于多个附加组。攻击者常用 -G root 把后门用户塞进 root 组
  • 排查时注意 -g（基本组）和 -G（附加组）的差异

四、持久化排查

4.1 开机启动项

开机启动分两套体系：CentOS6 及以前靠”运行级别 + init.d + rc.d”，CentOS7 开始靠 systemd（systemctl）。排查前先 cat /etc/redhat-release 分清版本，再按对应体系看。

一、CentOS6 体系：运行级别 + init.d + rc.d

1、什么是运行级别：Linux 给系统定义了 7 种运行状态，开机进入哪个级别，就只启动该级别对应的服务：

运行级别 含义
0 关机（默认级别不能设 0，否则起不来）
1 单用户模式（root 维护，禁远程登录，类似安全模式）
2 多用户命令行（不含 NFS）
3 完全多用户命令行（标准字符界面，服务器常用）
4 保留
5 图形界面（X11）
6 重启（默认级别不能设 6）

查看/切换：runlevel 查看当前级别，init 3 切到命令行模式。

2、开机进哪个级别：CentOS6 由 /etc/inittab 指定：

3、每个级别启动哪些服务：/etc/rc.d/rc[0~6].d/ 目录对应各运行级别，里面的文件名是软链接，指向 /etc/rc.d/init.d/ 下的真实服务脚本（/etc/init.d 是它的软链接）。

软链接命名规则：S/K + 两位优先级数字 + 服务名

  • S（start）= 进入该级别时启动，如 S10network
  • K（kill）= 进入该级别时关闭，如 K50netconsole
  • 中间的数字是启动/关闭优先级，1~100 越小越先执行

CentOS7 不再用运行级别 + init.d 管理服务，改用 systemd。原来的 service 命令会被重定向到 systemctl：

服务单元文件的位置（相当于”服务脚本”）：

  • CentOS7：默认带 /etc/rc.d/rc.local，但权限 644 不可执行，要 chmod +x 才会执行

  • 攻击者如果在 Ubuntu 上配 rc.local 后门，一定会同时 enable rc-local.service——两个点都要查

4.3 服务自启动

服务自启动是”让服务开机自动运行”，同样分两套体系：CentOS6 用 chkconfig 管理 init.d 服务，CentOS7 用 systemctl 管理 systemd 服务。排查前先 cat /etc/redhat-release 分清版本。

发行版差异（排查前先认清楚）：

  • CentOS/RHEL 7+ 和 Ubuntu 15.04+ 都已经是 systemd，service/systemctl 用法一致，服务文件都在 /usr/lib/systemd/system（系统自带）和 /etc/systemd/system（自定义）
  • 区别主要在：包管理器（CentOS 用 yum/dnf，Ubuntu 用 apt）、服务环境变量文件（CentOS 常见 /etc/sysconfig/xxx，Ubuntu 常见 /etc/default/xxx）、rc.local 行为（见 4.1）

一、CentOS6：chkconfig 管理 init.d 服务

原理：服务脚本放在 /etc/rc.d/init.d/（/etc/init.d 是它的软链接），脚本本身没有”开机自启”标记；chkconfig 的作用是在 /etc/rc.d/rc[0~6].d/ 下按运行级别建立 S/K 软链接指向 init.d 里的真实脚本——开机进入某个级别时，该级别 rc*.d 目录里的 S 开头脚本就会被启动（软链接机制见 4.1）。

二、CentOS7：systemctl 管理 systemd 服务

原理：服务单元文件（.service）放在 /usr/lib/systemd/system/（系统自带）或 /etc/systemd/system/（管理员自定义、优先级更高）。systemctl enable 做的也是建软链接——在 multi-user.target.wants 等目录下生成指向单元文件的软链接，开机进入对应 target 时服务自动启动。

认识一个真实的 .service 文件（Ubuntu 的 ssh.service）：

字段含义：

[Unit] 段——描述服务和依赖关系：

  • Description / Documentation：服务描述和文档位置
  • After=network.target auditd.service：等网络和 auditd 就绪后再启动
  • ConditionPathExists=!路径：路径不存在（! 取反）才启动，条件不满足就跳过

[Service] 段——定义怎么运行：

  • EnvironmentFile=-/etc/default/ssh：启动前加载环境变量文件，- 表示文件不存在也不报错
  • ExecStartPre=/usr/sbin/sshd -t：真正启动前先做配置语法检查
  • ExecStart=/usr/sbin/sshd -D $SSHD_OPTS：启动命令（-D 前台运行，把进程交给 systemd 托管）
  • ExecReload：reload 时执行（先重新检查配置，再发 HUP 信号）
  • KillMode=process：停止时只杀主进程
  • Restart=on-failure：异常退出自动重启
  • RestartPreventExitStatus=255：退出码 255 不自动重启
  • Type=notify：服务启动完成后主动通知 systemd
  • RuntimeDirectory=sshd：自动创建 /run/sshd 运行目录

[Install] 段——决定能否开机自启（systemctl enable 用的就是这段）：

  • WantedBy=multi-user.target：开机进入多用户模式（运行级别 3）时启动
  • Alias=sshd.service：给服务起别名，enable 时同时建别名软链接（所以 systemctl start ssh 也能用）

有 [Install] 和没有 [Install] 的区别：

  • 有 [Install]：可以用 systemctl enable 设置开机自启。enable 的实质就是在 WantedBy 对应目录（如 /etc/systemd/system/multi-user.target.wants/）建软链接，开机进 target 时自动启动；带 Alias 的话同时建别名软链接
  • 没有 [Install]：systemctl enable 会报错（单元文件没有安装配置），这类服务只能手动 start/stop，不能开机自启，除非被其他服务或 target 直接引用

start 和 enable 的区别（最容易混）：

  • systemctl start = 立即启动，重启后失效
  • systemctl enable = 设置开机自启（建软链接），不会立刻启动服务；想让本次会话也跑起来，两个都要执行

三、rc.local 方式：CentOS7 的 /etc/rc.d/rc.local 默认不可执行（644），攻击者改成 755 并写入启动命令即可开机执行，排查方法见 4.1。

一句话速查（30 秒过完这个点）：

  • CentOS6：chkconfig --list + ls -l /etc/rc.d/rc3.d/——查陌生服务名和 S/K 软链接
  • CentOS7：systemctl list-unit-files --type=service | grep enabled + ls /etc/systemd/system/multi-user.target.wants/——查自定义服务和软链接
  • Ubuntu：同样看 systemctl，额外查 systemctl status rc-local.service 是否被 enable
  • 所有发行版：/etc/systemd/system 下的自定义 .service 一律 systemctl cat 看 ExecStart
