Windows 入侵排查

2026-08-09 Windows ， 应急响应

0、前言

应急响应事件分类：

  • Web 入侵：网页挂马、主页篡改、Webshell
  • 系统入侵：病毒木马、勒索软件、远控后门
  • 网络攻击：DDoS 攻击、DNS 劫持、ARP 欺骗

排查流程：

排查顺序建议（拿到服务器先按这个来）：

  1. 先看现状：系统信息、网络连接、进程，找出可疑点
  2. 再查后门：账号、隐藏账号、克隆账户
  3. 然后查持久化：启动项、计划任务、服务，防止清了又复活
  4. 日志分析还原时间线
  5. 注册表、文件取证固定证据

工具清单见第七章。

1.2 网络连接与端口

TCP 状态速查（netstat 输出里看到的状态）：

状态 含义
LISTEN 本地监听，等待连接
SYN_SENT 主动外连，SYN 已发出等 ACK
SYN_RECV 握手进行中，收到对方 SYN
ESTABLISHED 连接已建立，正在通信
FIN_WAIT_1 / FIN_WAIT_2 主动关闭方：已发 FIN / 已收 ACK
TIME_WAIT 主动关闭方发完 ACK，等 MSL 超时
CLOSE_WAIT 被动关闭方收到 FIN，等本地关闭
LAST_ACK 被动关闭方已发 FIN，等对方 ACK
CLOSING 双方同时关闭，等 ACK

二、查后门：账号排查

2.1 用户与组

  • 先确认弱口令、远程管理端口是否对公网开放：直接问服务器管理员，别猜。
  • lusrmgr.msc 看本地用户和组，compmgmt.msc 也能看。
  • Administrators 组里出现陌生账号，直接禁用或删除。
  • 图形界面容易漏 $ 结尾的账号，用 net user 和注册表对账。

compmgmt.msc → 本地用户和组，右侧能看到全部账号：

账号删了目录还在，用户目录里能翻出行为痕迹（以 C 盘、用户 cracker 为例）：

  • C:\Documents and Settings\cracker\桌面 — 临时文件、下载文件（2003/XP 路径，2008R2+ 对应 C:\Users\cracker\Desktop）
  • C:\Documents and Settings\cracker\Cookies — cookie 里可能有敏感信息
  • C:\Documents and Settings\cracker\Recent — 最近访问的文件
  • C:\Documents and Settings\cracker\Local Settings\History — 上网历史
  • C:\Documents and Settings\cracker\Local Settings\Temp — 安装、解压产生的临时文件
  • C:\Documents and Settings\cracker\Local Settings\Temporary Internet Files — 网页缓存、下载文件

三、查持久化：启动项、计划任务、服务

3.1 启动项

【开始】→ 所有程序 → 启动目录（默认是空的），出现非业务程序就查。msconfig → 启动：命名异常的启动项取消勾选，并去对应路径删文件：

注册表三个键位重点看：

  • HKLM 的 Run 对所有用户生效，HKCU 只对当前用户，两个都要查。
  • 重点：键值指向 Temp、用户目录、随机名 exe；值名伪装成系统组件名（winupdate、svchost 之类）；RunOnce 出现程序也要查，这是攻击者常用的”跑一次自清理”位置，查晚了就没了。

组策略脚本启动：gpedit.msc → 计算机配置 / 用户配置 → Windows 设置 → 脚本(启动/关机)、登录脚本，攻击者常把 exe、bat、ps1 挂在这保活：

启动目录、Run/RunOnce 键、组策略脚本这些点，用 Autoruns（Sysinternals 工具）一键全查，能按标签页把启动项、计划任务、服务、驱动、COM 劫持、映像劫持等所有自启动点列全，比手工翻注册表快，还能按「隐藏 Microsoft 条目 / 隐藏 Windows 条目」过滤出非常规项。

3.2 计划任务

攻击者拿下最高权限后要做持久化：服务项和启动项是在开机/登录时跑 payload，计划任务则是在系统运行过程中挑一个未来时间点执行 payload。实现计划任务的方式有两种：at 命令（老版本系统常用）和 schtasks 命令（当前主流）。

at 命令介绍：

  • at 创建的任务要指定”几点执行”，适合定时回连、定时下载执行 payload。
  • 老系统上 at 可能被禁用，改用 schtasks。

schtasks 命令介绍（功能更全，现在攻击者基本都用这个）：

  • 攻击者套路：任务名伪装成系统服务名（MicrosoftUpdate、WindowsDefender 之类）；/sc minute /mo 1 高频回连；/ru SYSTEM 以系统权限跑；任务指向 %TEMP%、C:\Users\Public、下载目录。
  • 排查：taskschd.msc 图形界面看任务属性，”操作”标签里能看到程序路径和参数；命令行用 schtasks /query /fo LIST /v 全量导出再筛，比单条 findstr 更稳。
  • 重点：非业务程序、高频执行（/sc minute /mo 1）、指向临时目录或用户目录、任务名和路径对不上号。

3.3 服务

services.msc 看服务状态和启动类型，非业务服务重点看可执行文件路径：

注册表服务项：每个服务在 HKLM\System\CurrentControlSet\Services 下都有一个子键，重点看两个字段：

  • ImagePath：服务可执行文件的路径，指向 Temp、用户目录、随机目录的基本可判定恶意。
  • Start 值：2 = 自动启动，3 = 手动启动，4 = 禁用。自动启动的非业务服务重点查。

服务名常伪装成系统常见名（svchost、Windows Update 之类），但 ImagePath 会露馅，注册表和 services.msc 里对一下路径就能看出来。

红队反弹 shell、做持久化时常用 Instsrv.exe 装服务 + Srvany.exe 让任意程序以服务方式运行，注册表里会出现异常服务名。

3.4 辅助功能替换、映像劫持、登录脚本

这几个点不依赖开机启动，而是在用户登录、锁屏、按组合键等事件触发时执行后门，排查时容易漏。

辅助功能替换（粘滞键后门）： 系统自带的辅助功能程序（连续按 5 次 Shift 触发的 sethc.exe、放大镜 magnify.exe、旁白 narrator.exe、屏幕键盘 osk.exe、轻松访问 utilman.exe）被替换成 cmd.exe 或后门，3389 远程登录时按 5 次 Shift 就弹系统权限 shell：

映像劫持（IFEO）： 注册表里为正常程序添加 debugger 键值，指向恶意程序，用户一执行该程序就触发后门；配合 GlobalFlag + SilentProcessExit 可以在程序正常关闭后静默触发，更隐蔽：

Winlogon 登录触发： 用户登录时由 winlogon 运行的程序，正常值只有 userinit.exe，被追加 ,后门程序 即为异常：

Logon Scripts 登录脚本： 用户登录时执行，能优先于杀毒软件执行（利用系统执行优先级绕过杀软），值指向可执行程序即为异常：

屏幕保护后门： 屏保程序被改成后门路径，等待屏幕保护启动触发：

排查提示：辅助功能替换的利用前提是开了 3389，出事机器重点核对 sethc.exe 等文件；以上注册表点用 Autoruns 都能直接看到。

四、日志分析

4.1 日志类型与审核策略

三类日志：

  • 系统日志（System.evtx）：硬件、软件、系统问题
  • 应用程序日志（Application.evtx）：程序运行过程
  • 安全日志（Security.evtx）：登录、对象访问、进程追踪、特权使用、账号管理、策略变更。调查取证最常用

默认安全日志只记简单登录，要记录详细审计得先开审核策略：gpedit.msc → 计算机配置 → Windows 设置 → 安全设置 → 本地策略 → 审核策略，把需要审计的类别启用成功/失败：
