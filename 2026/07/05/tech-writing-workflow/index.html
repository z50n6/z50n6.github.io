我的技术写作工作流

2026-07-05 markdown ， writing

写了几年技术博客，摸索出一套稳定高效的写作工作流。核心原则：降低写作阻力，提高产出质量。

工具链

阶段 工具 原因
灵感收集 Obsidian 本地、快速、支持双向链接
初稿 VS Code + Markdown 熟悉的编辑环境
图表 Mermaid / Excalidraw 代码生成，可版本管理
校对 大声朗读 发现拗口句子
发布 Git Push → Vercel 自动化部署

文章模板

提示

动笔前先写三个要点：这篇文章给谁看、解决什么问题、读者看完能做什么。

审校清单

  • 代码示例能跑通
  • 没有超过 5 行的段落（太长难读）
  • 至少有一个图表或代码示例
  • 标题是动词/名词开头，不空洞
  • 结尾有可操作的下一步建议

成功

坚持这个流程 6 个月，技术博客的 Google 收录率从 30% 提升到 85%，平均停留时间翻了一倍。

一句话总结

引用

“好的技术文章不是靠灵感写出来的，是靠流程打磨出来的。”
