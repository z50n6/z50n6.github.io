SSRF 服务器端请求伪造

2026-06-28 WEB渗透 ， 基础漏洞

一、原理

服务器根据用户提交的 URL 发起 HTTP 请求。典型场景是”百度识图”——你给一个图片 URL，服务器去拉这张图然后做识别。

如果对用户输入的 URL 和远端返回的信息没有做恰当的校验和过滤，就产生了服务器端请求伪造（Server-Side Request Forgery，SSRF）。

三个条件：

  1. 服务器接受了来自客户端的 URL，并由服务器发出请求
  2. 对用户输入的 URL 没有恰当过滤，任意 URL 可被指定
  3. 对远端返回的结果没有校验，直接回显

二、危害

SSRF 的核心杀伤力在于把 Web 服务器变成内网的跳板。服务器能访问什么，SSRF 就能打什么：

  • 端口扫描，探测内网存活主机和服务
  • 内网 Web 应用指纹识别
  • 攻击内网未授权服务（Redis、MySQL、FastCGI 等 → 拿 RCE）
  • 读取本地文件（file:// 协议）
  • 云环境元数据窃取（AWS / GCP / Azure Instance Metadata）

协议 格式 用途

7.4 打 FastCGI（PHP-FPM）

前提：PHP-FPM 监听 9000 端口（Nginx + PHP 典型架构）+ 知道任意 .php 文件的绝对路径（如 /var/www/html/index.php）。

FastCGI 协议在发起请求时可以附带 FCGI_PARAMS 键值对，其中两个环境变量能改变 PHP 运行时行为：

变量 等效操作 能设的配置级别
PHP_ADMIN_VALUE 改 php.ini PHP_INI_SYSTEM / PHP_INI_PERDIR
PHP_VALUE 改 php.ini PHP_INI_ALL

攻击分两步——先开权限、再挂马：

  1. PHP_ADMIN_VALUE: allow_url_include = On → 允许远程/伪协议文件包含
  2. PHP_VALUE: auto_prepend_file = php://input → 目标 .php 执行前先 include FastCGI Body

结果就是：FastCGI Body 里塞什么 PHP 代码就跑什么。这比 Redis 写 WebShell 更干净——不需要知道 Web 目录路径，只需要知道任意一个 .php 文件的位置。

九、防御

层级 措施
协议白名单 只允许 http / https，禁止 file、gopher、dict
DNS 校验 getaddrinfo() 取真实 IP 后判断，不靠正则
禁止自动跟随重定向 每次 302 都重新校验目标 IP
过滤返回信息 不回显远端内容，统一错误信息阻止内网探测
内网服务加认证 Redis 设 requirepass、MySQL 设强密码
云环境 启用 IMDSv2（Token 认证）
