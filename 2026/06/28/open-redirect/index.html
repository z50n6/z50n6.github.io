URL 重定向（开放重定向）

2026-06-28 WEB渗透 ， 基础漏洞

一、是什么

URL 重定向漏洞（Open Redirect），一句话：网站接受用户输入的链接作为跳转目标，没有或仅做了很弱的校验，导致攻击者可以把用户从正常站点重定向到恶意站点。

危害不算”致命级”，但配合钓鱼非常好用——用户看到浏览器地址栏里是 trusted-site.com，一晃眼就被带到攻击者伪造的登录页面，毫无防备地输密码。

国外大厂一个任意 URL 跳转的赏金大概 $500～$1000，国内看运气。

二、产生原因

  • 开发时完全没意识到 URL 跳转也算漏洞
  • 用取子串、取后缀等简单方式校验，逻辑可被绕过
  • 对传入参数做域名拼接 / 剪切 / 重组的”骚操作”，适得其反
  • 底层语言 / 框架自带的 URL 解析库存在逻辑缺陷
  • 不同浏览器、服务器对 URL 标准解析的差异导致绕过

七、防御

措施 说明
白名单 跳转目标限定为已知合法域名，其余一律拒绝
相对路径 只接受相对路径跳转，拒绝完整 URL
Token 绑定 跳转前生成一次性 Token，不把真实 URL 暴露在参数里
用户确认页 跳转前弹确认页”你即将离开本站，是否继续？”
Referer 校验 配合跳转来源做二次校验，不能作为唯一防御
禁止伪协议 过滤 javascript:、data:、vbscript:

无效防御（别用）

  • 仅判断是否”包含”域名字符串 → evil.com?trusted.com 直接过
  • 仅判断是否以 https:// 开头 → 完全没用
  • 仅判断 URL 后缀（.com、.cn） → 形同虚设
  • 前端 JS 校验 → 抓个包就绕过去了
