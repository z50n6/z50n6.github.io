React 19 Server Components 深入理解

2026-06-20 frontend ， nextjs ， react

React 19 将 Server Components 作为一等公民，这意味着组件的运行环境从「客户端」扩展到了「服务端」。理解这一转变是写好 Next.js 应用的前提。

RSC vs SSR：两个概念

很多人把 RSC 和 SSR 混为一谈，但它们是正交的：

概念 含义 运行位置
RSC 组件在服务端渲染，不可交互 服务端（构建时或请求时）
SSR 在服务端生成 HTML 字符串 服务端（请求时）
Client Component 可交互的组件 浏览器

重要

RSC 的核心价值不是性能，而是让服务端能力（文件系统、数据库）直接参与组件渲染，无需 API 层。

Server Component 里不能使用 useState、useEffect 或浏览器 API。需要交互时，用 "use client" 声明客户端组件。

什么时候用 Client Component

graph LR
  A[需要状态?] -->|是| C[Client Component]
  A -->|否| B[需要浏览器API?]
  B -->|是| C
  B -->|否| D[Server Component]

成功

zBlog 的文章渲染管线就是典型的 Server Component 模式：数据层（lib/content）→ Server Component（页面）→ Client Component（搜索、主题切换等交互岛屿）。

总结

Server Components 让前端开发回到了「服务端渲染为主，客户端增强为辅」的模式，但这次我们拥有了 React 的组合能力和 TypeScript 的类型安全。
