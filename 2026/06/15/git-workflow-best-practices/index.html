Git 工作流最佳实践

2026-06-15 devops ， git

高效的分支管理能显著减少合并冲突和回滚成本。以下是我在实践中总结的一套轻量工作流。

分支策略

坚持三个核心分支：

  • main — 生产就绪，只接受 PR 合并
  • develop — 集成测试
  • feature/* — 功能开发

提示

单人项目可以用更简单的 main + feature/* 两分支模型。

提交信息规范

采用 Conventional Commits 格式：

graph TD
  A[git add] --> B[git commit]
  B --> C[git push]
  C --> D{CI 通过?}
  D -->|是| E[合并到 main]
  D -->|否| F[修复后重新提交]
  F --> A
  E --> G[自动部署]

重要

永远不要 git push --force 到共享分支。

常用操作速查

小心

git reset --hard 无法恢复，使用前务必确认已备份。
