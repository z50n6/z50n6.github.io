DNS 劫持原理与防护

一、DNS 是什么？

DNS（Domain Name System，域名系统）是互联网的「电话本」。

当你在浏览器输入 www.baidu.com 时，系统不会直接连这个字符串，而是先向 DNS 服务器发起查询，把域名翻译成 IP 地址（如 202.108.22.5），浏览器再用 IP 去访问目标服务器。

默认情况下，你的 DNS 通常由路由器或运营商自动分配（电信/联通/移动等）。这些 DNS 解析速度一般，且存在被篡改、被劫持的风险。

二、什么是 DNS 劫持？

DNS 劫持：攻击者在你访问域名时，将本应解析到的正确 IP 替换为恶意 IP，把你导向假冒网站。整个网络请求流程表面看起来正常，但中间某个环节已被篡改，用户往往难以直观察觉。

相当于有人在互联网「电话本」里替换了你的正确号码——轻则看到广告，重则账号密码被窃取。

2.3 DNS 劫持 ≠ 破解 HTTPS

协议 劫持后的表现
HTTP 可能直接看到钓鱼页面，用户不易察觉
HTTPS 浏览器通常报「连接不是私密连接」，证书域名不匹配

DNS 劫持主要影响流量导向，不能解密 HTTPS 内容。但配合钓鱼页面或用户忽略证书警告，仍可能造成账号泄露。

三、常见劫持方式

类型 发生位置 典型手段 技术门槛 影响范围
本地劫持 单台设备 恶意软件改 hosts、网卡 DNS 配置 低 单台设备
路由器劫持 局域网 入侵路由器，篡改 DHCP 下发的 DNS 低 连接该路由器的所有设备
中间人攻击 公共 WiFi / 局域网 ARP 欺骗 + 伪造 DNS 应答 中 同一网络内的用户
DNS 缓存投毒 DNS 服务器缓存 向缓存注入虚假解析记录 中–高 依赖缓存覆盖范围，可达大量用户
DNS 服务器攻击 权威/递归 DNS 入侵 DNS 服务器，篡改解析记录 高 成千上万用户
ISP / 注册商劫持 运营商或域名注册商 篡改解析记录、强制跳转、插入广告 需内部权限 极大，可波及整片用户群

几乎每一个环节都可能被利用，因此防护需要多层叠加，不能依赖单一手段。

四、危害

DNS 劫持的危害覆盖个人、企业乃至更大范围的网络安全：

危害类型 说明
账号密码泄露 假冒登录页骗取凭据
财产损失 银行卡盗刷、支付信息窃取
设备沦陷 植入后门，设备变为肉鸡（僵尸网络节点）
广告与诈骗 强制跳转广告页、钓鱼诈骗页面
隐私泄露 浏览行为、个人信息被监控或上传
企业级风险 大规模用户被重定向，业务中断、声誉受损
基础设施风险 权威 DNS 被攻破时，影响面可达千万级用户

本地和路由器劫持门槛低、普及性高；DNS 服务器级攻击门槛高，但一旦发生，波及范围极广。

五、为什么要换 DNS？

5.1 访问速度更快

运营商 DNS 节点少、调度不优，可能导致解析慢、游戏延迟高。阿里 DNS、腾讯 DNS 等公共 DNS 有全国节点，解析通常更快。

5.2 减少运营商劫持

更换可信公共 DNS 后，可规避运营商在 DNS 层面的强制跳转、弹窗广告、404 导流等问题。

5.3 提升安全性

优质公共 DNS 支持恶意域名拦截；进阶可配合 DoH/DoT 加密 DNS 查询，防止链路上被窃听或篡改。

六、推荐的公共 DNS

服务商 地址 特点
阿里 DNS 223.5.5.5 / 223.6.6.6 国内节点多，速度快，家庭用户常用
腾讯 DNS（DNSPod） 119.29.29.29 / 182.254.116.116 防劫持能力较强，游戏场景体验好
Google DNS 8.8.8.8 / 8.8.4.4 全球知名，国内访问可能较慢
Cloudflare DNS 1.1.1.1 / 1.0.0.1 注重隐私，支持 DoH/DoT

八、如何识别 DNS 劫持

单一工具难以保障，需多管齐下：

8.1 行为异常（最直观）

  • 输入正确网址却跳转到广告页、无关网站
  • 页面内容与预期不符，但 URL 看似正常
  • 频繁出现 HTTPS 证书警告

九、被劫持后如何修复

发现疑似劫持后，按以下顺序处理：

9.1 断网

立即断开网络连接，防止进一步信息泄露。

9.2 清除 DNS 缓存

9.3 恢复设备配置

  • 检查并恢复本机 DNS 设置为自动或可信公共 DNS
  • 检查 hosts 文件，删除可疑条目
  • 检查浏览器代理、VPN 等网络扩展设置

9.4 恢复路由器

  • 登录路由器后台，检查 DNS 和 DHCP 设置
  • 修改路由器管理密码（若怀疑被入侵）
  • 必要时恢复出厂设置并重新配置

9.5 全盘杀毒

使用杀毒软件全盘扫描，清除可能篡改 DNS / hosts 的恶意程序。

9.6 运营商问题

若确认是 ISP 劫持，保留证据（截图、nslookup 结果、时间记录）并向运营商投诉或向监管部门反映。

十、预防措施

10.1 个人 / 家庭

措施 说明
使用可信公共 DNS 定期确认 DNS 配置未被篡改
路由器强密码 避免默认密码，启用 WPA3（若支持）
固件升级 定期更新路由器固件，修复已知漏洞
启用 DoH / DoT 加密 DNS 请求，降低中间人篡改风险
不连不可信 WiFi 公共网络不访问敏感账户，或使用 VPN
忽略证书警告 HTTPS 报证书错误时不点击「继续访问」
开启 MFA 即使密码泄露，多因素认证仍可提供保护

10.2 加密 DNS（DoH / DoT）

传统 DNS 走 UDP 53，明文传输，易被中间人篡改。DoH/DoT 将查询加密，是防护现代 DNS 攻击的核心手段之一。

在软路由或 NAS 上部署 AdGuard Home：

  • 自定义 DNS 上游（指向阿里 / Cloudflare 等）
  • 拦截广告、追踪器、恶意域名
  • 查看全网 DNS 查询日志，发现异常解析

10.5 企业级防护

措施 说明
自建内部 DNS 减少对外部不可控 DNS 的依赖
启用 DNSSEC 校验 DNS 应答完整性，防止缓存投毒和篡改
网络监控 部署 DNS 流量监控，检测异常解析和泄露
定期巡查 检查 DNS 记录、设备配置、日志
应急演练 模拟 DNS 劫持场景，验证响应流程
ARP 防护 防范局域网中间人 DNS 欺骗

网络安全意识和日常维护是第一道防线：定期检查设备设置、更新固件、使用复杂密码，能持续降低被劫持风险。

十二、防御对照表

攻击方式 防御措施
本地 hosts / DNS 篡改 杀软扫描；定期检查 hosts 和 DNS 设置
路由器 DNS 篡改 强密码；固件升级；定期检查 DHCP 下发 DNS
中间人 DNS 欺骗 静态 ARP 绑定网关；不连不可信 WiFi；DoH/DoT
DNS 缓存投毒 DNSSEC；使用支持 DNSSEC 验证的递归 DNS
DNS 服务器攻击 基础设施加固；监控；最小权限；DNSSEC
ISP / 注册商劫持 换公共 DNS；DoH/DoT；保留证据投诉
钓鱼页面 不忽略 HTTPS 证书警告；核对 URL；开启 MFA

十三、速查清单

13.1 日常预防

  • DNS 已设为可信公共 DNS（路由器或本机）
  • 路由器使用强密码，固件为最新版本
  • （可选）已启用 DoH / DoT / AdGuard Home
  • 公共 WiFi 上不访问敏感账户

13.2 定期自查

  • 多 DNS 源对比解析结果，确认无异常
  • hosts 文件无异常条目
  • 路由器 DNS / DHCP 配置正常

13.3 发现异常后

  • 立即断网
  • 清除 DNS 缓存
  • 恢复本机与路由器 DNS 设置
  • 全盘杀毒扫描
  • ISP 问题保留证据并投诉
