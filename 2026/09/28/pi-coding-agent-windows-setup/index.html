Pi Coding Agent Windows 原生环境配置指南

2026-09-28 AI赋能 ， Pi Coding Agent

这套配置不碰插件开发，也不讲 Pi 的核心机制，只解决一件事：把 Pi 装在 Windows 原生环境（而不是 WSL2）之后，怎么让它别在 bash 上栽跟头。

前置依赖四个工具，缺一个后面的配置都白搭：

工具 用途
ripgrep（rg） 文件内容 / 文件名检索
pi-coding-agent 本体
PowerShell 7（pwsh） 替掉 bash 当默认 shell
Windows Terminal 承载终端快捷键

一、用 pwsh 替掉 bash

先把结论摆前面：Windows 上不要用默认 bash 或第三方 bash 工具，两个原因。

路径格式对不上。 WSL 那套 bash 认的是 /mnt/c/Users/...，而模型在 read、write、读 system prompt 的时候，默认吐出来的是 C:/Users/...。两边格式不一致，调用 bash 工具时路径识别错误几乎是必然的。

命令本身也不兼容。 不少在 Linux 上跑得好好的 bash 命令，换到 Windows 要么行为变了，要么直接不可用。

现在的模型（GPT-5.6、DeepSeek 4 Flash 这类）写 PowerShell 脚本已经相当熟练，没什么理由继续将就 bash。改配置文件 %USERPROFILE%/.pi/agent/settings.json：

遇到乱码就加这段，别犹豫。实测 Win10 上不加必定乱码；Win11 有时不加也能正常显示，具体原因还不清楚，但补上没坏处。

三个细节：

  • [Console]::OutputEncoding 管的是 PowerShell 自己怎么解码输出，chcp.com 65001 管的是控制台代码页 —— 后者是原生程序会继承并读取的那份，两个都留着。
  • [System.Text.UTF8Encoding]::new($false) 里的 $false 是关掉 BOM 输出，别改成 $true，否则每次命令回显前面都会多出几个不可见字节。
  • 如果 profile 里要写中文注释，存成 UTF-8 with BOM 更保险。pwsh 7 无 BOM 也能正常解析，但 PowerShell 5.1 读无 BOM 的 UTF-8 会把中文注释解成乱码。
